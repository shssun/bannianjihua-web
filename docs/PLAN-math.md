## 2. 定位（v2 修订）

**不是**「函数工具」，而是 **「高中数学易误解点」的可视化工具**，函数是第一类。

三条设计原则（全部由老板的话推出）：

1. **敢取边界值** —— 参数必须能取到 `0` 与负值。教科书默认 `a≠0`，
   而学生最容易漏掉的正是**退化情形**；**能取到 0 才是真正暴露误解**。
2. **图是主、文字是辅** —— 先让图象说话，再用一句话点破。
3. **加场景 = 加一个数据对象** —— 这就是「创建模式」；以后加三角/数列，不用重写工具。

**差异化**（调研确认是块空白）：现有工具（含国内几乎同名的竞品）绝大多数只做
**「框住 x 的区间」**（拖 x₁/x₂ 看局部值域），**没人做「拖函数自身的参数」**。

## 4. 场景清单

### 阶段 1（6 个常见形态，随 T-024 一次交付）

| # | 场景 | 参数 | **关键易误解点** |
|---|---|---|---|
| 1 | `y = ax² + bx + c` ⭐老板指定 | a, b, c（**均含 0 与负**） | **a=0 时二次项消失 → 退化为直线**（最经典的"忘记讨论 a=0"）；a 变号 → 开口翻转、**值域随之翻转**；b 变 → 对称轴 `x=−b/(2a)` 移动；c 变 → 上下平移（过 `(0,c)`） |
| 2 | `y = kx + b` | k, b | `k=0` → 退化为**常函数**（不是"斜率为 0 的一次函数"） |
| 3 | `y = k/x` | k | k 正负 → 一三 / 二四象限；**x=0 处必须断开，不得画出穿屏竖线** |
| 4 | `y = aˣ` | a（a>0） | 0<a<1 减 / a>1 增；**值域恒 (0,+∞)，不随 a 变**（反直觉） |
| 5 | `y = log_a x` | a（a>0 且 a≠1） | 定义域恒 (0,+∞)；**a=1 不允许** —— 滑到 1 附近要给提示 |
| 6 | `y = x + a/x` | a | 拐点 (√a, 2√a)；`a<0` 变「飘带函数」单调无最值；`a=0` 退化成直线 |

### 阶段 2（补齐函数 + 让「易误解点」成形）

| 场景 | 关键点 |
|---|---|
| `y = a(x−h)² + k` | 顶点式三参数 ↔ 一般式的对应 |
| `y = √(x−a)` | 定义域左端点随 a 平移；值域恒 [0,+∞) |
| `y = \|x−a\|` 及 `\|x−a\|+\|x−b\|` | 最小值 = \|a−b\|；数轴距离和 |
| `y = (ax+b)/(cx+d)` | 分离常数；竖直/水平渐近线；值域**挖掉 y=a/c** |
| `y = x^α` | α 变化 → 定义域/值域**断崖式跳变** |
| `y = x²−2ax+3, x∈[1,3]` | **定轴动区间的分类讨论**（高考最大丢分点） |

### 阶段 3（依「易误解点全清单」调研结果扩展）

三角、数列、解析几何、不等式…… 由正在跑的 `math-traps` 调研给清单，
按「**可视化性 = 强**」优先做成新场景或新工具。

## 6. 技术方案（沿用 v1 调研结论，未变）

- ✅ **手写 Canvas 2D** —— 零第三方库、零外部请求、产物天然是一个 `index.html`
- ❌ **不用 `eval` / `new Function`** —— ① 将来加 CSP（`script-src 'self'`）会被拦；
  ② 同源上下文里外部粘贴的表达式能读本机 `localStorage` 与同源资源
- ❌ **Desmos 不可用** —— 必须 API key（静态站藏不住）+ 必须请求 `www.desmos.com`；免费层仅限个人非商业/90 天评估
- ❌ **GeoGebra 不可用** —— 整套**仅非商业**免费（UI/语言文件 CC BY-NC-SA 4.0），商用须签协议
- ❌ plotly / echarts / chart.js 体积劝退；🅱️ 备选 function-plot（MIT / 59.5KB gzip / 可自托管）
- ⚠️ **必须做对**：`y = k/x` 在 x=0 处**不得画出穿屏竖线** ——
  遇 `NaN/±Infinity` 记断点并 `moveTo` 断开；相邻两点 y 均有限但**符号相反且 |Δy| > 1.5×屏高** → 同样断开
- 高 DPI：canvas 尺寸 × `devicePixelRatio` + `setTransform(dpr,0,0,dpr,0,0)`

### 9.1 全清单的结构发现（决定架构要留多大余地）

80 条易误解点调研得出一个结论：**「全面覆盖」不可能由单一工具形态完成**。按所需交互分成五类：

| 工具形态 | 覆盖章节 | 典型条目 |
|---|---|---|
| **2D 曲线 + 参数滑块** ← 本工具 | 函数 / 基本初等 / 导数 | `a=0` 退化、判别式 Δ、幂函数定义域跳变、基本不等式取等不到 |
| 单位圆 + 曲线联动 | 三角 | 周期 `2kπ`、`sin(2x+φ)` 实际平移 `φ/ω`、正弦定理两解 |
| 坐标系 + 图形 | 向量 / 解析几何 | `a·b=0` ⇒ 垂直（不是"有零向量"）、斜率不存在、椭圆 `a²=b²+c²` |
| 项 / 和 的动态序列 | 数列 | `Sₙ−Sₙ₋₁=aₙ` 需 `n≥2`、等比 `q=1` 分母为 0 |
| 分布图 | 概率统计 | 正态关于 `x=μ` 对称、独立性 |

⚠️ **立体几何整体偏「中」** —— 需要 3D 交互而非单参数滑块，**与 2D 工具分模块**，不强行塞进来。

→ **所以本工具不追求「大而全」**：把「2D 曲线 + 参数」这一类做扎实、做好用；
其余形态按「可视化性 = 强」分批另立工具。
**集合 `high-school-math` 正是为容纳它们而留的口子**（不用改集合 id 就能加新工具）。
